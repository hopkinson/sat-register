# SAT 本机控制台

在 Windows 本机管理考生查位与报名任务。控制台与浏览器均在本机运行，**无需购买服务器、部署 Docker 或安装 Chrome 插件**。

---

## 1. 快速启动

### 首次安装依赖
需 **Node.js 18+**，在项目目录执行：

```powershell
npm install
npx playwright install chromium
```

### 日常启动
```text
双击 [启动.bat]  (或运行 npm start)
       │
       ▼
start-local.js 检查依赖与浏览器
       │
       ▼
自动打开 http://127.0.0.1:3000 控制台
```

> [!IMPORTANT]
> - **保持后台运行**：保持启动命令行窗口开启，电脑切勿休眠。
> - **关闭网页 ≠ 停止任务**：关闭浏览器控制台页面不会中断后台任务；在启动窗口按 `Ctrl+C` 才会停止服务及所有浏览器任务。
> - **单实例运行**：请勿同时启动多个服务实例。

## 2. 全流程操作与人机协作图

```text
[1. 全局设置] 配置全局 SAT 账号密码 (可选配置 YesCaptcha 密钥 / 自动接受考试规则)
      │
      ▼
[2. 创建任务] 填写姓名、考期、国际考区与考点 (可选上传 ≤5MB JPG/PNG/WebP 照片)
      │      * 国家/地区、考期、考点均从 College Board 官方接口实时拉取
      ▼
[3. 启动监控] 点击任务卡片「启动监控」→ 弹出独立资料目录浏览器 (data/profile_<任务ID>)
      │
      ├─► 登录认证：自动读取当前全局凭证，按名称选择 Password 方式登录
      │
      ├─► 首页分流：优先续办目标考期的未完成报名 (无法唯一定位时保留窗口转人工)
      │
      ├─► 个人资料：保留官网已有学校/年级/问卷，不按位置代填
      │            └─ 遇弹窗 / 必填缺失 / 未推进 ──► [待人工核对] ──(人工处理)──► 自动恢复
      │
      ├─► 考试规则：默认人工当次确认；开启自动接受后自动滚到底部、勾选并 Continue (失败转人工)
      │
      ├─► 考期与查位：按年份分组匹配并核对完整考期 (不匹配绝不乱选其他日期)
      │   │
      │   ├─ 遇 Arkose 验证码：配置 YesCaptcha 后自动打码注入 (最多 6 次，间隔 ≥30s)
      │   │                  未配置 / 失败 / 未推进 ──► [待人工核对] ──(浏览器内处理)──► 自动恢复查位
      │   └─ 遇选座 hCaptcha：在任务浏览器内人工完成 ──► 持续核对控件/考期/考点后自动接续提交一次
      │
      ▼
[4. 选座后核对] 控制台显示「待人工核对」(说明停在确认页 / 后续页 / 需验证码 / 结果未确认)
      │        * 上述状态均不证明已锁位，不生成锁位倒计时，且本机版绝不自动提交付款
      ▼
[5. 人工支付与归档] 在官网核对考期、考点及金额后人工支付 ──► 控制台点击「确认已付款」
                    * 完成或删除任务会自动清理该任务的照片、截图及浏览器资料目录
```

## 3. 各环节自动化与人工边界

| 环节 | 自动化行为 | 转「待人工核对」条件与恢复方式 |
| :--- | :--- | :--- |
| **全局凭证** | 启动任务时读取当前全局 SAT 账号密码（无需每任务重复填写） | 修改全局配置后，**运行中的任务需停止并重新启动**才会生效 |
| **首页续办** | 优先定位并续办目标考期的未完成报名 | 无法唯一定位时保留浏览器，由人工进入正确报名 |
| **个人资料向导** | 保留官网已有学校、年级和问卷答案，绝不按下拉框位置盲填 | 遇到弹窗、必填项缺失或 `Continue` 未推进时暂停；在浏览器处理后自动恢复 |
| **考试规则** | 默认人工确认；设置开启「自动接受考试规则」后自动滚底、勾选并点击 `Continue` | 任一步骤失败即转人工当次确认 |
| **Arkose 验证码** | 配置 YesCaptcha 密钥后自动识别并注入（单次运行最多尝试 6 次，间隔 ≥ 30 秒） | 未配置密钥、打码失败或注入后页面未推进时暂停；在浏览器完成后**自动恢复查位**，无需重启 |
| **考期匹配** | 按年份分组匹配并核对完整考期 | 无法确认时等待人工处理，绝不误选其他日期 |
| **选座 hCaptcha** | 持续核对官网控件、目标考期和考点，人工验证完成后自动接续一次选座提交 | hCaptcha 回填令牌不等于官网通过；直接在任务浏览器完成验证即可（若会话过期不可沿用；提交接口报错时保留现场，不自动重放） |
| **锁位与支付** | **不生成锁位倒计时，绝不自动提交付款**（即使旧设置保存过自动扣款开关） | 选座尝试后一律停在浏览器供人工核对考期、考点与金额并完成付款 |

## 4. 任务管理与状态说明

- **编辑任务**：支持修改考期、补传/更换/移除证件照（支持 ≤ 5 MB 的 `JPG`、`PNG`、`WebP`）。
  - 运行中需先暂停；已完成任务不可编辑；已保存的地区不可修改。
  - 改期后需重新确认考点（若官网考期接口加载失败，仍可按已保存考期保存）；保存后保持「未启动」并保留历史日志。
  - **注意**：编辑仅修改本地配置，**不会同步修改官网已有报名**；若已进入报名流程，请人工核对官网信息。
- **服务重启与恢复**：单个任务停止或关闭浏览器后可重新启动。服务重启后，旧运行状态统一恢复为「未启动」，请先核对官网实际状态再手动启动。
- **资源清理**：点击「确认已付款」完成任务或删除任务时，自动清理该任务的照片、截图与 `data/profile_<任务ID>` 目录（数据库记录按操作保留或删除）。

## 5. 系统架构与数据安全

```text
启动.bat / npm start (及旧极速 BAT 入口)
  │
  └─► start-local.js        [环境自检] 检查 Node 依赖、Chromium 浏览器，启动本地服务
        │
        └─► server.js       [核心服务] 仅监听 127.0.0.1:3000，负责任务管理、日志推送、数据持久化
              ├─► public/index.html      [前端界面] Web 控制台
              ├─► sat-engine.js          [自动化引擎] Playwright 驱动独立浏览器窗口
              └─► data/                  [本地存储]
                    ├─ db.json           任务与全局配置 (明文存储，切勿上传或共享)
                    └─ profile_<任务ID>  各任务独立的浏览器登录态与缓存目录
```

> [!WARNING]
> - **隐私与安全**：服务仅监听 `127.0.0.1`，不开放局域网或公网访问。`data/` 目录下的配置与登录状态以明文保存在本机，**严禁上传、共享或在未加密情况下备份**。
> - **历史文件隔离**：`api-fast-locker.js` 与 `sat-monitor.user.js` 为保留的历史实现，不参与本机控制台运行，**请勿同时启用**。若浏览器仍安装有旧插件，请先将任务录入本机控制台，再停用或移除旧插件。（项目内的 Python、视频帧和 OCR 文件仅用于分析操作录像。）

## 6. 接口验证与已知限制

- **官方实时数据源**：新建任务时的国家/地区名单、考试日期、考点均每次从 College Board 官方公开接口实时获取，不保存本地兜底列表；任一接口加载失败时需刷新重试，切换考期或地区会自动清空旧考点。
- **考区范围**：当前新建任务仅支持**国际考区**（美国考区需邮编与距离查询，暂未支持；已有旧任务记录仍保留）。
- **缓存与风控提示**：官网公开字典及考点服务可能存在官方缓存，界面显示的“获取于”仅代表本地拉取时间，实际考位以登录后报名查询为准。官网页面结构、风控与登录步骤可能随时变化，自动查位与选座不保证报名成功。
- **并发建议**：尚未测定多任务并发上限，建议先用 **1 个任务** 跑通确认流程，再逐步增加并发。
- **实测文档与自测**：
  - 官网实测登录、已有报名、考试规则、考点查询步骤及自动化差异详见 [官网操作步骤与实测记录](docs/official-flow.md)。
  - 运行 `npm test` 可使用临时数据及模拟官网验证本机服务、全局凭证更新、重试、浏览器交接和日期匹配（不读取真实账号，不触碰真实官网与付款）。
