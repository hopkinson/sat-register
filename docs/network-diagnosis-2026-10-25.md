## 结论与当前状态

后续修正：本记录中 hCaptcha“通过”只证实应用回调曾解禁按钮，不能证明官网控件完成验证。新排查发现 SDK 响应仍为空，需人工正常验证后再对照锁位接口。当前浏览器已保留，详情见 [锁位排查记录](lock-failure-diagnosis-2026-10-25.md)。以下网络对照结论仍有效。

原节点「香港年付3-美国13 0.2x」访问 College Board 的稳定性较差，是页面资源长期加载不完的主要诱因。现已把 Clash「🐟 漏网之鱼」分组切换为「香港年付3-美国82 奈飞」。本机 TUN 开启、rule 模式，报名项目没有配置独立代理；实测 College Board 连接链确认为该分组和所选节点。该分组也控制其他命中 MATCH 的流量，不是只针对 College Board 的规则。

新节点下真实登录、报名页面加载、考点查询、Zone B 选座确认、hCaptcha 验证以及设备指标同意均已推进。随后官网 `save-reg-request` 返回 HTTP 500，错误为 `RegAdminTestCenterService.assignSeat failed`。这只证明分配座位失败，不能确定具体业务原因，也不能证明成功锁位。已保存错误截图并停止任务，未进入收银台、未付款。

## 测试证据

- 逐节点探测 MySAT：测试 35 个实际节点，32 个成功。节点延迟不是整页完成时间。
- 八个候选节点分别对 MySAT、SAT 报名页、kiwi 脚本各探测两次。原美国13仅 3/6 成功；美国12、美国82、加拿大、JP81、HK21均 6/6 成功。美国1、美国2均在 kiwi 地址出现失败。
