# SAT 官方数据来源与实时获取调研

调研日期：2026-10-22。本文记录只读访问官方网页、官网发布的 JavaScript 和匿名 GET 接口的结果；本次未登录、未提交报名、未读取账号凭证。源站实现和响应头均可能变化。

## 官方来源调查

### 1. 国家／地区列表可以匿名取得，无需先登录

官方入口：[SAT Test Center Search](https://satsuite.collegeboard.org/sat/test-center-search)。直接读取 HTML 确认，该页加载 [官方查询应用 main.js](https://satsuite.collegeboard.org/modules/site/aru_test_center_search/app/dist/main.js?tn9d5g)。该前端的国家查询函数实际请求：

`GET https://atlas.collegeboard.org/apricot/prod/4.11.5/api/CBCountries.json`

[国家／地区 JSON 官方源](https://atlas.collegeboard.org/apricot/prod/4.11.5/api/CBCountries.json) 本次匿名请求为 HTTP 200，根对象含 `countries` 数组，共 245 条。条目含 `countryName`、`iso`、`country` 等字段。抽查：`Hong Kong / hk`、`Macao / mo`、`China / cn`、`United States / us`。

官网查询应用只排除 `countryName === 'United States'`，将 `iso` 转为大写作为值，并按 `countryName` 排序；没有按 `country === true` 过滤。**Macao 的 `country` 为 false，因此不能将这个字段当作“可报名”或“应显示”的标志。**245 条是通用国家／地区字典，不证明每个地区在每个日期都有 SAT 考点。

该 URL 带 Apricot 版本，是官网当前实际使用的公开资源，不是查到文档承诺长期稳定的第三方开放 API。实施时应将版本地址集中在一处，并为格式变化明确报错；不要悄悄返回本地快照。

### 2. 考期也有公开官方 JSON

同一份官方前端源代码把考期入口设为：

`GET https://sat-admin-dates.collegeboard.org/`

[官方考期 JSON](https://sat-admin-dates.collegeboard.org/) 本次匿名请求 HTTP 200，返回 5 场（2026-11-07、2026-12-05、2027-03-06、2027-05-01、2027-06-05）。字段包括 `adminId`、`asmtEventId`、`eventFormattedDate`、`eventDisplayDate`、`eventInternational` 及报名截止时间。

应用应优先使用 `eventFormattedDate` 的 `YYYY-MM-DD` 值；不要把 `eventStartTs` 转到本机时区后截日期。以上是本次响应快照，不是未来考期的固定清单；此入口也不是登录后某一考生的报名资格证明。

### 3. 考点查询路径和美国分支

官网同一前端的查询函数实际调用 [官方考点服务](https://aru-test-center-search.collegeboard.org/prod/test-centers)：

- 国际：`?date=<eventFormattedDate>&country=<ISO大写>`。
- 美国：`?date=<eventFormattedDate>&zip=<邮编>&country=US`，然后在前端按返回的 `distance` 和用户选择的距离过滤。

因此当前本地 UI 的“美国本土（全区任意抢）”不能直接等同于官网支持的全国查询。美国应有邮编和距离；若本次只做国际考区，应明确将美国流程留到单独适配。

### 4. “每次访问官网”不等于“绕过官网所有缓存”

本次匿名请求附带 `Cache-Control: no-cache`、`Pragma: no-cache`，国家 JSON 仍返回 `Cache-Control: public, max-age=3600`。公开搜索 HTML 也有缓存响应头（本次 `public, max-age=300, s-maxage=2628000`）。官网前端源码本身还给国家列表配置 `staleTime: 1800000`，给考期配置 `staleTime: 300000`。

这些头和配置证明官方允许缓存，并不能单独证明某条响应已经过时。自建服务可以做到：每次刷新都发起新的上游网络请求，不读取本地文件／数据库快照／应用缓存，要求重新验证，并给浏览器响应 `Cache-Control: no-store`。但不能保证官方 CDN 或源站数据库没有缓存，也不能把本机获取时间写成“官网数据更新时间”。

### 5. 真实考位以登录后的报名查询为准

[官方 Registering 指南](https://satsuite.collegeboard.org/sat/registration/online-registration/registering) 明确区分考点位置与报名时看到的可用座位，要求登录账号完成报名流程。公开字典和考点清单不能替代该流程。

本项目已有 [登录后官网实测记录](official-flow.md)：2026-12-05 香港 Zone A 在公开接口显示 `seatAvailability: true`，登录后的报名页面却显示 `No seats available.`。这是已有项目记录，并非本次重新登录复验；不应据此推导差异一定由缓存造成。

### 6. 已验证与待验证边界

已验证：官方页面实际引用的脚本、脚本中的三个公开数据入口与参数规则；国家 JSON 和考期 JSON 的匿名 HTTP 200、结构、部分字段；上面列出的缓存头。

尚未验证：这些公开接口的服务级别承诺、允许轮询频率、稳定性保证；公开字典与登录后某一场报名国家下拉框是否完全相同；登录后内部接口的认证参数、响应结构和缓存行为；真实选座／锁位确认行为。本次不应声称已经验证“秒级实时考位”。

验证方法：Web 搜索与打开官方说明页；PowerShell `Invoke-WebRequest` 直接 GET 官方 HTML、其实际引用的 main.js、JSON 源；只输出必要的响应结构、样例和缓存头。未使用第三方查位网站作为事实依据。

## 本项目现状与差距

- [public/index.html](../public/index.html) 的 `formRegion` 写死九个地区；`loadOfficialCenters()` 才发起考点查询。`openAddSheet()` 打开表单就加载考点，实施动态地区后须改成先地区、后考点。当前标签“目标考区 / 城市”实质是国家／地区，应改为“考试国家／地区”；城市可从考点地址展示，不另造一份城市字典。
- [server.js](../server.js) 的 `GET /api/sat-centers` 每次调用 Node fetch 请求官方考点接口，没有本地考点文件／应用结果缓存，返回浏览器时设置 `Cache-Control: no-store`。这只能说明本机实现，不能说明上游无缓存。
- 主代理于北京时间 2026-10-22 18:41 左右直接 GET 既有香港接口（2026-12-05），请求带 `no-cache`，返回 HTTP 200、3 个考点；响应 `Cache-Control: public, max-age=154, s-maxage=300`。该头允许共享缓存复用最多 300 秒，不表示每条结果必然延迟 300 秒。Zone A 此次仍报告 `seatAvailability: true`，未在本次登录对照。
- `loadOfficialCenters()` 非编辑模式失败时仍会留下旧选项；地区变更又默认保留原考点值。因此只加一个在线地区接口还不够：失败／切换条件后不能继续把旧列表当作本轮成功结果。
- [sat-engine.js](../sat-engine.js) 已有按任务隔离的浏览器、人工登录／验证码／条款交接，以及 `queryTestCenters()` 的本轮网络请求和卡片重绘检查。后者目前是监控判断，不是完整列表接口，不能直接假定已经能为表单提供所有考点。
- Worker 当前先按地区英文名称选中，失败后按代码兜底，并吞掉选中失败；动态名单应优先按官方代码选中，再读取实际值核对，不匹配时停止本轮查询。当前默认香港也不能在动态加载失败时替用户悄悄选中香港。
- 编辑接口目前只允许更改考期／考点／照片，地区不可编辑。本轮若仅替换新建表单的数据来源，可继续保持该范围；保存的任务地区是用户历史选择，不应伪装为本轮在线结果。

## 方案比较与建议

| 方案 | 适合解决的问题 | 成本与限制 | 建议 |
| --- | --- | --- | --- |
| 后端直接取公开官方 JSON／考点接口 | 打开表单时在线获取国家地区和候选考点 | 无需登录；官方仍允许缓存，通用地区字典不保证当天有考点 | 本次截图需求首选 |
| 复用登录后的报名浏览器读取下拉框／本轮查询卡片 | 查询该账号、该考期在报名流程中显示的选项和考位 | 登录、验证码、条款、报名阶段及并发访问都要处理，明显较慢 | 用于查位；若要求名单与登录页完全一致也用此方案 |
| 直接重放登录后的内部接口 | 在已验证接口后减少页面解析 | 当前尚未捕获认证契约、请求参数及缓存行为，不能凭空实现 | 先抓取并比对实际请求，再决定，暂不作为交付前提 |

### 推荐先交付的最小范围

1. 在现有 `server.js` 增加 `GET /api/sat-regions`，每次 GET 固定官方 JSON URL；限制超时、检查 HTTP 状态和 `countries` 结构。仅返回必要字段，例如 `{source, fetchedAt, regions:[{code,name}]}`。`fetchedAt` 是获取时间，不是源数据更新时间。
2. 无本地名单、数据库快照、内存 TTL 缓存或离线兜底。浏览器请求 `cache:'no-store'`，本机响应 `Cache-Control:no-store`；上游请求要求重新验证。保留上游缓存策略的事实，不承诺端到端零缓存，也不靠随机参数宣称绕过源站缓存。
3. 前端打开新建表单时显示加载状态，成功后按官网名称与 ISO 代码生成选项，再加载考点。中文名称若需要可仅作为展示层翻译，选项是否存在、身份代码以本次官方数据为准。官方字典共 245 条；国际模式按官网排除美国，不按 `country` 布尔字段过滤。
4. 失败时显示“官网地区列表加载失败，请重试”，禁用依赖该结果的考点选择和新建提交；明确区分失败、成功但没有考点、仍在加载。切换日期／地区时立即清空依赖考点并使旧请求失效，采用现有请求序号方式防止慢响应覆盖新条件。刷新开始后不得继续使用旧结果冒充新结果。
5. 新建任务服务端检查地区代码和必要字段，不允许空值默认为香港；Worker 用代码选中官网控件并核对实际值。代码是身份，英文名称主要用于展示，不将 `Macau` 与 `Macao` 的拼写差异变成流程失败。
6. 国际流程和美国流程明确分支。若要保留美国支持，需一起补邮编／距离和任务字段及 Worker 对应处理；不能只在国际名单末尾加一个 US 就宣称支持全美。
7. 报名监控继续以登录后的本轮查询为依据；公开接口的 `seatAvailability` 不升级为锁位证据。不在本次地区名单需求中重写登录引擎或加入新的独立登录浏览器。

公开考期接口已找到，可作为后续独立小改动，用于替代任意日期输入；与本次地区名单不强行捆绑。

### 如果要求所有选项与登录报名页完全一致

实施前先在已有、目标考期正确的报名页，只读记录国家下拉框的代码和名称；点击查询时记录准确的请求方法、URL、请求体、认证方式、响应及渲染结果，敏感字段不落入研究文档。用同一账号、同一考期和地区比较公开字典、公开考点及登录后结果。

优先复用 `sat-engine.js` 现有浏览器生命周期，增加受控的只读查询能力；不能为同一浏览器资料目录再启动第二个实例。查询操作与监控循环串行化，避免表单刷新改动监控中的日期／地区。尚无浏览器或登录失效时返回需要人工处理的状态，不能把旧截图／旧 DOM 作为新查询结果。条款必须维持现有当次人工交接。读取列表的路径必须停在读取结果，不复用后续选座、照片、订单推进动作。

该方案有创建任务前尚无任务浏览器的问题；若决定让新建表单依赖登录结果，需要额外设计显式“连接官网”入口和会话归属，而非偷偷借用正在运行的其他任务。因此仅为国家下拉框采用它不划算。

## 验收与下一步

实施后至少验证：首次打开没有本地预填名单；每次刷新确实发起上游请求；断网／HTTP 失败／格式错误都明确报错且不能提交；Macao 等地区不会被错误过滤；慢请求和切换日期／地区不会串结果；保存后 Worker 实际选择的代码正确；旧任务仍能显示其历史配置；美国不会走国际查询逻辑。测试使用模拟上游，再做一次真实匿名只读请求确认字段，登录后的准确性另做同条件对照。

本次仅完成调研与方案分析，未修改应用代码、未登录重验、未执行报名或选座。推荐下一步先实现公开官方地区名单在线加载；考位保持登录后查询，分清“本次获取时间”和“真实可报名状态”。
